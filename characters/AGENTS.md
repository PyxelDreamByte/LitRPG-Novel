# Character Instructions

- Resolve the owning work manifest before using a character. Character URIs, profiles, arcs, knowledge, relationships, and state are work-bound and must remain beneath that `work_root`.
- Do not merge or cross-reference characters from another work without an explicit cross-work contract approved by the Author. Similar names never imply identity.
- In `EVALUATION`, fixtures and simulated state remain noncanonical and cannot update authoritative character records.
- The Author alone accepts character canon and arcs.
- Keep identity/history, current state, knowledge, belief, presentation, and reader disclosure separate.
- Never grant a character knowledge from an outline, another POV, private CAL0 data, or an agent's context pack.
- Derive changing state from accepted chapter deltas; do not hand-edit snapshots into competing canon.
- Validate action against motive, capability, resources, conditions, relationships, location, and CAL0 mechanics.
- Preserve stable character IDs and cite the event that caused every state change.
