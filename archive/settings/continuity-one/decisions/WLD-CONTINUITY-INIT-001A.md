# WLD-CONTINUITY-INIT-001A — Initiate the Continuity One shared-setting shell

Decision URI: `author-decision://world/WLD-CONTINUITY-INIT-001A`

## Question

What stable identity, cross-work authority topology, and constitutional scope
should initiate the first real shared setting without establishing fictional canon?

## Options

### Identity

- `SET-INIT1A` — stable `setting://continuity-one` identity with a provisional
  display title.
- `SET-INIT1B` — choose a fiction-bearing title now and derive the permanent slug.
- `SET-INIT1C` — postpone initialization for a non-canonical naming brief.

### Authority topology

- `SET-INIT2A` — one shared core with governed compatible work-local overlays.
- `SET-INIT2B` — require every setting fact to live only in shared canon.
- `SET-INIT2C` — begin with explicitly branching continuities.

### Constitutional scope

- `SET-INIT3A` — define a layered foundation decision map without answering it.
- `SET-INIT3B` — use only a minimal authority charter.
- `SET-INIT3C` — predefine exhaustive approval surfaces for every anticipated domain.

## Recommendation

Select `SET-INIT1A`, `SET-INIT2A`, and `SET-INIT3A`. Together they establish a
durable, reusable authority container while avoiding premature fictional assumptions.

## Author selection

The Author selected `SET-INIT1A`, `SET-INIT2A`, and `SET-INIT3A` on 2026-08-12.

## Rationale and evidence

- A neutral stable identity does not smuggle fictional claims into the setting.
- A shared core supports consistency across later works, while governed overlays
  preserve work-local flexibility.
- A layered unanswered map exposes dependencies without deciding them.
- Evidence: explicit Author selections on 2026-08-12.

## Consequences

- Create `worldbuilding/settings/continuity-one/` as a `DRAFT`/`PROPOSED` shell.
- Keep `adopting_work_ids` empty.
- Allow future work-local overlays to add compatible facts.
- Require a separate Author decision for any proposed contradiction or override.
- Leave all fictional foundations unanswered.
- Keep `WLD-SOUL-001A` and `WLD-PRENATAL-001A` unadopted and unassumed.

## Dependencies and conflicts

- Dependencies: none.
- Conflicts: none.

## Residual unknowns

- Final display title.
- Every fictional foundation question.
- Future setting adopters and their explicit default selections, if any.

## Reopening conditions

- The Author changes the stable identity or authority topology.
- A later approved continuity model requires branching authority.
- Repository governance changes the setting-first boundary.
